# Shoutan: agent guide

Shoutan (手談) is Go, the board game, for Android: Expo SDK 57, React Native 0.86, TypeScript and Hermes. It plays offline, and online with the family through Supabase. `docs/playing.md` describes the app, and `docs/glossary.md` names its concepts (shown game, viewer, Who, count, marking); use those names in code and docs.

## Read first

- **Expo or React Native APIs:** Expo breaks APIs every SDK. Check `https://docs.expo.dev/versions/v<major>.0.0/` for the major version in `package.json`, and add packages with `npx expo install <pkg>`.
- **Where code goes:** `docs/architecture.md` has the layers, the file map, state and a move end to end. Keep it true when the shape changes.
- **The bot, playouts, sound and motion, wording, languages, licences, touch on Android, the checks:** `docs/development.md`.
- **Schema, migrations, hosting, reports, releases, publishing:** `docs/releasing.md`.

## Rules

- **Online games replay identically on every phone.** A change to the rules, `seal`, the state digest or the genesis string bumps `RULES_VERSION` and keeps old games replayable. Randomness is seeded, and events hold no clock time.
- **Game logic lives in `src/go/`**, pure TypeScript, written test-first in `src/go/__tests__/`. Offline play never depends on the network.
- **Every player-facing string goes through `t()`**, with the same key in `fi.ts`, `es.ts` and `it.ts`. Copy is plain and beginner-friendly.
- **Hosted Go is the schema `go`** and the roles `go_owner` and `go_reports`, in a Supabase project shared with other apps. Touch nothing outside it, and keep every migration working for the released app. Hosting changes go into `npm run infra` and its test; the owner runs it.
- **Native config lives in `app.config.ts`.** `android/` is generated by `npx expo prebuild`.

## Definition of done

Run each check the change can affect, once.

1. Every change: `npx jest` while working, `npm run verify` once before committing. Screen behaviour gets a screen test in `src/__tests__/app.test.tsx`.
2. Rendering, touch, animation, native config or startup changed: `npm run build:local`, install the APK, `npm run test:offline`, and look at the screenshots in `e2e-output/`.
3. `src/net/`, `src/online/`, the online screens or the schema changed: `npm run test:online`.
4. After device tests, comment on the pinned `Device log` issue with what was checked, and update its list of what isn't. Commits leave that issue unmentioned, because a release closes every issue its commits mention.
5. In a session with the owner, push `main` to `origin` and to the mirrors `.husky/pre-push` allows, without waiting for CI.

Publishing the source is the owner's step: agents run only `npm run publish:public -- --dry-run` and report what it lists. Ideas and bugs are GitHub issues.
